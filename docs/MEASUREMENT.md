# Measurement and testing framework

This is the rig that guides development and judges every strength claim.
Three layers, from fast to slow:

1. **Rust unit tests** (`cargo test`) — protocol parsing, position handling,
   search behaviour. Run on every change.
2. **UCI compliance suite** (`tools/uci_compliance.py`) — black-box protocol
   test over stdio, usable as CLI or pytest. Run before every PR.
3. **Benchmarks** — `tools/bench.py` (speed + tactics) and
   `tools/play_match.py` (Elo vs Stockfish). Run for every strength change,
   before and after.

## Unit tests

```bash
cargo test
```

Covers `position` (FEN roundtrip, kiwipete counts, atomic illegal-move
rejection), `search` (`go` parsing, deterministic choice, `searchmoves`,
null move on terminal positions) and `uci` (handshake, all `go` flavours,
infinite/ponder/stop, bad input, mate reporting).

## UCI compliance suite

```bash
python3 tools/uci_compliance.py --engine ./target/debug/rustfish
python3 -m pytest tools/uci_compliance.py -q   # same checks as pytest
```

59 checks: handshake, `isready` before/after `uci`, required options,
`setoption` (valid, unknown, malformed), `ucinewgame`, debug/unknown-command
tolerance, stop-without-search, startpos/FEN/move-list positions, every `go`
limit type, `searchmoves` restriction, malformed positions (engine must survive
and answer from the previous position), `go infinite` + `stop`, ponder +
`ponderhit` + `stop`, 30 seeded fuzz positions with legality verified by
python-chess, terminal positions (`bestmove 0000`), clean `quit`.

## Speed bench

```bash
python3 tools/bench.py --engine ./target/debug/rustfish
```

Reports handshake latency, mean/p95 `go depth 1` latency over 200 seeded
middlegame positions, and positions/sec. Today this measures protocol
overhead; once real search lands, rerun with deeper `go` limits to track NPS
and time-to-depth. JSON is saved to `tools/results/`.

## Tactical suites

`tools/data/mate_in_1.epd` (20) and `mate_in_2.epd` (10) were generated by
`tools/make_tactical_epd.py` (seed 7) and every line was independently
re-verified: each `bm` provably mates in N. Regenerate deterministically with
the same command. `bench.py` scores the engine with `go movetime 200` per
position. A bestmove scores when it mates (in 1) or forces mate (in 2),
verified with python-chess — not only when it equals a listed `bm`, because
positions can hold several mates and the engine may find a shorter one than
the stored solution.

## Matches vs Stockfish (Elo anchor)

```bash
python3 tools/play_match.py --pairs 10 --sf-elo 1320
python3 tools/play_match.py --pairs 25 --sf-elo 2400 --tc 15+0.15
```

Uses `cutechess-cli` with a 12-line opening book (`tools/data/openings.epd`,
auto-generated), resign adjudication (3 moves ≤ −700cp) and draw adjudication
(10 moves ≤ 15cp after move 40). Stockfish 18 anchors the scale via
`UCI_LimitStrength` + `UCI_Elo` (verified range 1320–3190 on the local
binary); both engines run Hash=32, Threads=1.

Statistics: score, Elo difference with 95% confidence interval (delta method
on per-game scores), and likelihood of superiority (LOS), computed from the
match PGN independently of cutechess's own Elo line, which is kept as a
cross-check. PGN + JSON summary go to `tools/results/`.

Match sizing guide: ±100 Elo at 95% needs roughly 100 games at 50% score;
near the target anchor run at least 50 pairs. Calibrate a new engine version
at 1320 first (cheap signal), then spend games at 2400.

## CI

`.github/workflows/ci.yml` runs `cargo fmt --check`, `cargo clippy`,
`cargo test`, the pytest compliance suite and a bench smoke test on every PR.
Full matches stay manual — they take too long for CI — but every strength PR
must quote its match result.
